# MindFlow Zotero 全流程逻辑复审与 5.0.2 修复记录

日期：2026-09-28。基线：本目录上一轮的 5.0.1。复审后的代码、前端构建及安装包均为 5.0.2；5.0.1 原文件保存在 `backups/verified-5.0.1-*`，原安装包也仍保留。本文补充上一轮《审查与修复清单》，没有把原来 42 项重复计算成新发现。

## 1. 复审结论和证据边界

上一轮解决了多种“选 A 打开 B”的身份混淆，但没有充分验证宿主记录、编辑状态、工作区文件和附件之间的完整闭环。本轮扩大真实 Zotero 测试后，发现并修复了上下文同步、立即关闭、跨运行环境异常、并发删除和快照等残留问题。

最直接的三个证据：

- 5.0.1 在真实 Zotero 中，修改标题后立即关闭标签，再打开仍显示旧标题。基线原生测试 12/13 通过，失败项是立即关闭保存。证据：`baseline-5.0.1-native-results.json`。
- 将不同来源的同 ID 附件隔离到新工作区后，画面正确并不代表宿主标签的 `docId` 已正确更新。扩大测试发现旧 ID 和新建标签的空 ID；这会误导撤销关闭及会话恢复。本轮核对了实际文件、标签数据和附件来源，而不只检查标题。
- 模拟另一窗口更新文件后，第一次保存能拒绝旧版本，但旧实现的内部读操作会更新编辑器记住的版本号，导致第二次重试错误地获准覆盖。另一个原生场景中，Gecko 宿主异常来自不同运行环境，`instanceof Error` 失效，版本冲突没有进入副本保护分支。

所有原生测试使用隔离的 Zotero 数据目录与测试论文。没有修改用户正在使用的文献库、没有调用真实 AI 服务或 WebDAV 账户，也没有发布到 GitHub。原生宿主版本是 Zotero 10.0.3。测试启动器仅向解压后的测试安装包追加回归脚本加载；不向生产运行代码注入补救 API。

## 2. 数据身份和责任边界

| 数据 | 正确身份 | 用途与限制 |
|---|---|---|
| 文献条目 | 文献库 ID + 条目 key；或带库范围的 Zotero URI | 决定文献归属。显示标题与裸 key 均不能跨库决定身份。 |
| 物理导图附件 | 文献库 ID + 附件 key | 决定来源、标签复用及归档更新目标。复制文件可能保留相同内部文档 ID。 |
| 本地导图 | 工作区文档 ID | 决定本地文件和跨导图链接。不同附件内部 ID 冲突时分配独立工作区 ID。 |
| 编辑版本 | 当前文件 revision + 本窗口预期 revision | 宿主同一队列内比较并提交；不得通过失败后的读操作提升预期版本。 |
| 窗口或标签 | 真实所属 iframe/window + 当前实际文档 ID | 前端切换后必须同步宿主；不能只依赖最初打开参数。 |
| 版本快照 | 快照 ID + 所属文档 ID + 快照内部文档 ID | 三者必须对应。恢复内容时保持当前已经确认的附件关联。 |
| 删除状态 | 持久删除标记 | 标记写成即逻辑删除。主文件、旧首选项或备份仍存在，也不能自动复活。 |

当前完整链路：

```text
列表/右键/条目侧栏/PDF 阅读器
  → 取得明确选择，解析库范围与父条目
  → 按真实附件来源选择标签或独立窗口
  → 初始动作与后续动作按顺序执行
  → 校验树结构，按附件来源找本地记录；同 ID 不同来源隔离
  → 显示导图，同时同步宿主的实际 docId、附件来源和标题
  → 本地保存：宿主队列内检查删除标记及预期 revision
  → 单文档原子替换、读回核对；列表由有效文件派生
  → 快照：宿主队列内追加/删除，保留并发版本
  → 归档：同一队列检查版本、内容和实际父条目/附件身份
  → 写附件并读回，关联结果再持久化到本地
  → 关闭：同步捕获编辑器状态和未提交节点文字，由宿主持有写盘任务
  → 冲突时保留独立副本；不向原文献自动归档副本
  → 撤销关闭/会话恢复：从当前 docId 对应的有效文件恢复
```

## 4. 完整操作和失败处理矩阵

| 操作 | 输入/状态检查 | 输出与失败行为 |
|---|---|---|
| 打开已有关联导图 | 精确库范围、附件身份、父条目、文件内容身份、完整树 | 来源正确；同 ID 不同来源隔离；失败明确提示，不打开其他论文。 |
| 同父文献多份导图 | 附件 key 各自不同 | 分别打开和恢复；forceNew 真实创建独立文档和附件。 |
| A→B→A、快速点击 | 初始动作队列、切换序号、保存完成检查 | 较早请求不能覆盖较后选择；最后一次真实选择生效。 |
| 节点增删、撤销重做 | 当前导图和节点 ID、历史栈 | 修改正确根节点；切换时清理历史；原生插入/撤销/重做验证。 |
| 本地自动保存 | 完整树、删除标记、预期 revision | 宿主单文件替换与读回；失败显示错误，不宣称已保存。 |
| 多窗口同文档 | 各自持有的版本必须对应磁盘版本 | 旧版本拒绝；编辑内容保留为解除关联的冲突副本。 |
| 归档附件与大纲 | 指定文献库/父条目/附件、版本与正文；归档目标只读检查 | 附件文件和登记归属均核对。大纲失败与附件成功分别报告。 |
| 删除与后台任务 | 宿主同一队列内检查 revision | 删除标记有效；旧读、旧保存、后续归档均不能复活记录。 |
| 立即关闭标签/窗口 | 同步抓取 doc、关系线及未提交节点文字 | 宿主持有保存；冲突保存独立恢复副本；一般 I/O 错误进入日志。 |
| 撤销关闭/进程重启 | 宿主记录必须是真实 docId | 加载有效本地文件，保留树和精确附件来源，不重新生成附件。 |
| 主文件损坏 | 备份内部 ID 和结构也要匹配 | 从有效 .bak 恢复；下次提交保存损坏原件副本并读回新正文。 |
| 历史快照恢复 | 快照归属、内部文档 ID、当前 revision | 恢复内容并保持当前归档身份；恢复前再留快照。 |
| 全工作区备份恢复 | 全部输入先验证；同 ID 用明确预期版本 | 每篇文档受版本保护；中断报告进度与恢复点。 |
| AI 草稿 | 准备记录绑定原 URI、有效期、配置、取消状态；草稿自动归档关闭 | 此轮审查了控制路径，未调用服务商；不把引文片段匹配当作科学结论已验证。 |
| WebDAV | 本地保存先完成，云端状态独立；下载数据仍需结构/大小校验 | 此轮审查了控制路径，未连接真实服务器。附件归档成功不等于云备份或跨设备同步成功。 |
