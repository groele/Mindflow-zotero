# 深度逻辑审查与修复（2026-10-07）

本次检查基于当前 10.0.4 工作区，覆盖宿主消息、附件身份、保存版本、文档切换、关闭恢复、编辑历史、收件箱、快照和备份恢复。此前记录仅用于定位，测试结果均重新运行。修改前源码与原 XPI 保留在 `backups/audit-20261007/`。

## 已修复的问题

| 问题 | 原因与修复 | 验证 |
|---|---|---|
| 恢复预检查与写入之间可能覆盖另一窗口新建的同 ID 文档 | 新增 `restore-deleted` 模式：允许解除删除标记，同时仍要求磁盘版本等于预期版本；宿主和开发存储路径保持一致 | 前端注入预检查后的并发创建；宿主复活与版本冲突测试 |
| 快照数组含空值、错误所属 ID、非法时间或损坏载荷仍进入界面 | 读取和修改前校验每条快照结构、文档 ID、载荷与时间；损坏数据保留原状并报错 | 前端及宿主损坏数据不覆写测试 |
| 重复快照 ID 被静默忽略 | 导入预检查与宿主添加均拒绝重复 ID | 验证任何文档写入前就停止 |
| 目标本地快照损坏时导图可能先写入再失败 | 在恢复文档之前预检所有目标快照存储 | 测试损坏历史时不创建目标文档 |
| 冲突副本的内部链接仍指向原导图 | 自动保存、切换保存及关闭恢复副本均重定向自引用文档链接；跨文档链接保留 | 关闭冲突副本自链接断言及已有链接重定向测试 |
| 异步快照回滚可能覆盖期间的新输入 | 应用统一执行回滚；保存当前草稿后锁住编辑，拦截键盘、粘贴、拖入与输入事件；无论成功失败均释放锁 | 原生 UI 延迟写入与恢复期间 Tab 检查 |
| 快照回滚未清除旧多选，历史列表不更新 | 回滚清空编辑与多选状态、重置历史、刷新包含回滚前恢复点的列表 | 原生 UI 历史刷新检查 |
| 快照恢复与其他备份操作可重复触发 | 备份面板共用操作锁并禁用对应按钮；统一处理异常，丢失的快照明确报错 | 构建检查与原生回滚流程 |
| 备份文件读取前未限制体积，FileReader 失败反馈不足 | 工作台改用 `file.text()` 并在读取前检查 20 MB 上限，异常进入统一错误提示 | 类型检查及构建 |
| 导入历史不遵守设置的快照保留上限 | 按文档批量合并，按时间排序后应用 10–50 范围内的配置上限 | 60 个快照导入后仅保留默认 20 个 |
| 文档已恢复但收件箱/快照失败时提示不准确 | 错误明确给出已保存文档数量、失败阶段与恢复快照保留情况 | 注入收件箱损坏后的部分恢复报告测试 |
| 首次创建默认文档返回未保存对象 | 返回实际写入后带版本号的文档，使内存与磁盘对象一致 | 首次创建默认导图与磁盘完整对象相等的测试 |
