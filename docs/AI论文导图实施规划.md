# MindFlow × llm-for-zotero：AI 论文导图实施规划

本规划合并本次会话的全部要求：复用 llm-for-zotero 的已配置模型，保留模型及推理强度选择，允许按文章部分阅读，建立固定科学分析模板，为实验论文提供不同导图风格，并用本地真实文章完成模型调用和生成验证。

## 1. 产品目标与两款插件的分工

用户流程：选择一篇 Zotero 文章 → 选择读取范围 → 本地预览实际资料 → 选择分析框架和导图风格 → 选择上游模型与推理强度 → 生成可编辑、可核验的导图 → 用户审阅后归档。

| 能力 | llm-for-zotero | MindFlow |
|---|---|---|
| 模型供应商、接口、认证和密钥 | 作为配置与调用的唯一来源 | 读取已配置模型，不另建供应商和密钥页面 |
| 模型请求、协议、流式响应和推理参数适配 | 直接使用公开 `api.agent.runTurn` | 提供结构化任务和取消信号，不自建 HTTP 请求 |
| Zotero 文章与 PDF 数据 | 保留它自己的功能 | 读取所选文章并整理本次确认的资料 |
| 分析框架与固定分支 | 按本次提示词输出 JSON | 定义模板、章节选择、证据核对、导图转换 |
| 编辑、布局、主题、草稿与归档 | 不承担这些导图职责 | 复用现有编辑器和存储系统 |

依赖基线是本机已安装且已检查公开接口的官方 llm-for-zotero 3.9.11。版本号不能代替能力检查：启动时检查插件就绪及 `agent.runTurn` 是否存在。上游接口源码：[agent/index.ts](https://github.com/yilewang/llm-for-zotero/blob/main/src/agent/index.ts)。不复制其模型请求实现或能力注册表。

## 2. 五种读取范围

| 模式 | 模型实际接收 | 用途 | 必须提示的限制 |
|---|---|---|---|
| 仅摘要（默认） | Zotero 摘要 | 快速判断是否值得精读 | 实验条件、对照和机理证据可能不足 |
| 仅引言 | 本地识别的引言文字 | 背景、知识缺口、研究目标 | 不能据此断言最终实验结果 |
| 仅结论 | 本地识别的结论文字 | 作者总结、贡献与展望 | 不能替代结果和方法的核验 |
| 摘要＋引言＋结论 | 三部分实际取得的文字 | 较低成本的结构化概览 | 缺少正文证据或实验参数时明确留空 |
| 全文 | 本次页数与长度范围内的 PDF 文字，必要时分段 | 精读、机理判断和复现参数整理 | 读取上限、扫描 PDF 和补充材料覆盖有限 |

读取范围与分析深度是两种设置。读取范围决定哪些文字允许发送；快速/深入决定对这些文字单次分析还是分段整合。深入模式不会自动扩大到全文。

PDF 边界：现有 Zotero `PDFWorker.getFullText` 接口提供本地文字提取，未验证其支持任意章节或末页直接读取。因此首版仅摘要完全跳过 PDF；其他章节模式在本地提取文字后按标题定位，只把选中部分发送给模型。不能把这种实现宣称为 PDF 文件只读取了指定章节；节省的是模型输入量。后续仅在 Zotero 提供稳定页范围接口时优化本地提取耗时。

摘要缺失流程修订：已有条目摘要时仍跳过 PDF；缺失时允许在 PDF 前 5 页范围内定位明确的摘要标记与结束边界，只发送该段。未能可靠定位时说明原因，并由用户明确选择其他范围；不将正文作为摘要。读取范围固定显示，避免无资料时陷入只有禁用按钮的状态。

识别中英文及编号标题；遇到目录重复标题、标题无法定位或提取不完整时显示缺失部分，不静默发送全文。用户明确切换范围后重新准备资料。笔记、划线和评论作为额外来源，默认不发送，用户可主动加入。

预览显示实际准备字符数、缺失章节、是否截断及预计请求次数。字符数是可直接核对的指标；未使用模型实际分词器时不把估算字符数称为精确 token 数，不承诺固定比例的 token 节省。

## 3. 固定分析框架

所有模板共用三个证据等级：论文原文支持、分析推断、待解决。逐字引文匹配只证明文字来自输入，不能证明模型对该段文字的解释一定正确。

### 实验研究

框架：研究问题—材料与条件—测量及对照—定量结果—机理证据—贡献与边界。

固定分支：研究背景、知识缺口、核心问题、材料体系、实验条件、研究方法、作用机理、主要发现、解决的问题、创新意义、局限、后续验证。

材料：组分、层数、相态、堆叠、衬底、界面、掺杂或处理及对照体系。

条件：实际报告的温度、激发波长、功率、磁场、电压、气氛、时间、制备参数；保留单位、范围和参数所对应的对象。原文未报告时不猜测。

机理：原因—过程—结果；把作者解释、直接证据与分析者推断分开。对照、独立表征与竞争解释的排除是判断机理的依据，相关性不能直接变成因果结论。

发现：测量量、变化方向、数值、基准、误差和条件。尽量一项判断对应一段可核对的证据。

### 理论与计算

框架：物理问题—有效模型与假设—参数与边界—求解—机理—可观测预测—验证。

固定分支：背景、缺口、问题、研究体系、模型与假设、参数与条件、方法、机理、理论预测、验证、局限、后续验证。

记录原文实际采用的模型、自由度、哈密顿量或控制方程、近似及忽略项。核查量纲、极限、收敛、参数可辨识性、实验对应量与可证伪性。不能因求解器成功就断言物理模型已验证，不能把计算曲线称为实测结果。

### 机理辨析

框架：现象与问题—测量条件—证据链—候选机理—竞争解释—区分性验证。

固定分支：背景、缺口、问题、材料、条件、方法、发现、机理、竞争解释、验证、局限、后续验证。

重点回答每条证据支持什么、不能证明什么，还有哪些解释没有排除，什么独立实验能够区分这些解释。不得为了填满模板编造竞争机理或检验结果。

### 综述与对比

框架：领域问题—材料与条件—方法分类—机理路线—代表发现—共识与分歧—开放问题。

固定分支：背景、缺口、问题、材料、条件、方法、研究路线分类、机理、发现、共识与分歧、局限、后续方向。

只比较本次输入出现的研究。区分综述转述与直接验证，不补造参考文献；不同温度、定义、归一化方式和测量条件下的数值不能直接合并。首版支持单篇综述，不扩展为自动全库文献检索。

## 4. 实验论文的四种导图风格

| 风格 | 内容重点 | 固定分支数 | 默认布局 | 信息密度 |
|---|---|---:|---|---|
| 完整研究解析 | 完整科学故事与贡献边界 | 12 | 双侧思维导图 | 每分支最多 5 项 |
| 速读概览 | 做了什么、材料与条件、发现与机理 | 8 | 双侧思维导图 | 每分支最多 2 项 |
| 证据链 | 假设、设计、结果、解释、竞争机理、验证 | 10 | 向右逻辑图 | 每分支最多 5 项 |
| 实验复现 | 材料、步骤、条件、结果及复现检查 | 9 | 向下层级图 | 每分支最多 5 项 |

风格既决定分析任务，也决定实际导图分支与布局。主题颜色继续由现有编辑器管理；不把更换配色当成另一种分析框架。节点写简明判断，详情、实验条件和原文引文放入节点备注。核心分支展开，缺失项标为待补充；生成后继续允许编辑和改变布局。

模板定义集中在 `chrome/content/research-templates.json`。宿主提示词、前端选择器和导图转换读取同一份定义，避免三个位置分支不一致。保存模板 ID 和版本，后续模板更新不自动改写已有导图。

## 5. 模型和推理强度选择

模型菜单来自上游已配置条目；默认优先其最近使用的可调用模型。本次选择不修改上游聊天默认值。

模型显式配置了推理能力选项时，继承它的 ID、名称和启用状态，包括自定义强度；完整能力配置仅传给上游，不向 iframe 暴露参数体和密钥。上游明确不支持推理时禁用强度选择。

上游公开 Agent API 未提供完整的每模型推理强度表时，只提供通用请求选项并明确由上游映射，不宣称每个选项均被模型实际执行。不得复制上游能力注册表或自行拼接推理请求参数。

不支持的 WebChat、Codex App Server、Claude Code 对话系统给出具体提示；没有上游插件时不能假装生成成功，不能转为独立 MindFlow 模型请求。

## 6. 调用与数据完整性

所有摘要分析、PDF 分段和最终整合都使用同一公开上游 API。结构化 JSON 通过宿主验证后再构造导图。空结果、格式错误、未完成运行和工具调用中止不能创建成功导图。

每次请求只传确认的资料，不附带聊天历史、当前 Zotero 条目对象或可扩大的文献范围。记录服务名、API 名、实际运行 ID、模型、请求强度、读取范围、资料缺口及模板版本。

缓存区分模型、推理强度、模板、读取范围、资料选择和分析深度；换范围必须新建预览，不复用全文预览冒充仅摘要。模型配置变化时重新确认。取消释放监听器并阻止后续保存，分段重试可复用同范围内已成功部分。

生成物先保存本地 AI 草稿，不自动创建 Zotero 附件。修改失败不覆盖原导图；归档沿用现有身份与并发保护。密钥不进入导图、预览、文档和测试报告。

## 7. 分阶段实施与验收

| 阶段 | 实施内容 | 验收门槛 |
|---|---|---|
| A：上游接入 | 移除独立连接、读取模型、公开 API 调用、取消与错误 | 请求只经过上游；模型/强度传递正确；缺依赖明确失败 |
| B：模板与风格 | 单一模板定义、选择器、提示词、固定分支、布局 | 7 套预设均有效；切换改变实际分析结构；模板有版本 |
| C：读取范围 | 摘要跳过 PDF；引言/结论识别；预览与范围约束 | 未选正文不出现在模型输入；缺失章节不回退全文 |
| D：证据与保存 | 来源匹配、参数保留、运行记录、草稿编辑与持久化 | 四个实验核心维度有结构；引文可核查；无自动归档 |
| E：端到端验收 | 在隔离 Zotero 配置中验证资料选择、上游调用、草稿生成和持久化 | 分开报告确定性集成测试与真实模型结果；不把模拟响应表述为真实模型分析 |
| F：回归与打包 | 宿主测试、前端测试、类型/构建、原生回归、包校验 | 最终包与验证源码一致，测试代码和密钥不进入包 |

确定性本机端点适合协议、选择器、异常和存储回归；若进行真实模型测试，应单独说明实际使用的资料、请求和人工核对范围，不能把模拟响应表述为真实模型总结。

## 8. 维护与验收边界

实现以统一模板定义、上游公开 API 和现有 Zotero 偏好存储为准。用户预设由独立配置目录保存，包含自定义提示词、研究内容模板和呈现模板；导图记录生成时采用的模板与来源信息。新建预设、修改、删除、设默认、损坏存储保护和重新读取均应有可重复测试。

宿主测试覆盖上游请求与资料范围，前端测试覆盖选择状态、草稿转换与外观，真实 Zotero 隔离测试覆盖偏好持久化及重启恢复。全量原生回归与单项功能验收分别报告；测试版本必须固定，失败用例必须保留，任何未覆盖的模型质量、PDF 结构、平台和备份路径都要明确说明。
